# 首页学习统计与排行榜

## 启用

先运行 Supabase SQL Editor 中的 `supabase/migrations/202610210001_learning_rankings.sql`，再发布前端。脚本可重复运行，只新增计时、昵称与统计函数，不修改原有 `practice_attempts`、`mistakes` 数据和权限。前端仍可兼容脚本未运行的状态：分页读取当前用户已有答题记录，明确提示计时与榜单尚未启用，不显示模拟排名。

本轮用户已反馈脚本运行成功；正式匿名 API 检查返回 `401 / 42501`，确认函数存在且未向未登录访客开放。登录后的页面读取、计时和排名仍需结合实际浏览器验收；本地数据库测试不能替代正式站验收。

数据库函数采用固定空 `search_path`、`auth.uid()` 和最小授权；新表开启 RLS，浏览器不能直接写时长。依据 [Supabase 数据库函数文档](https://supabase.com/docs/guides/database/functions) 与 [RLS 文档](https://supabase.com/docs/guides/database/postgres/row-level-security)。不在前端放置数据库管理密钥。

## 统计规则

- 首页默认累计，可切换北京时间今天及前六天。三项个人统计与三个榜单使用同一范围。
- 答题数量按云端提交题次累计，含解答题自评，重复练习也计入；不会把课程页只在本地展示的自测冒充云端提交。
- 正确率仅含选择、填空；排除 `self:` 自评和全部现有 `-written-` 题目。显示一位小数，所选范围至少完成 20 次客观题才进入正确率榜。
- 相同成绩并列排名（如 1、1、3），每榜最多展示 10 名同学；个人排名单独返回，不受前十限制。
- 排名默认不参与。用户在首页填写 2～20 字昵称并点击参与后，其他登录用户才可看到该昵称与汇总表现。退出后立即从榜单排除，个人记录保留。接口不返回他人的邮箱、用户 ID、答案、草稿或逐条记录。
- SQL 直接聚合原有答题表，不受 REST 默认 1,000 行返回上限影响。

## 学习时长

仅登录用户在课程内容路径 `/grade1/...`、`/grade2/...`、`/grade3/...` 与 `/practice/` 上计时；年级目录、综合训练目录、首页、报告、登录和错题列表不计时。历史时长不估算。

每 15 秒发送心跳，只在页面可见、窗口有焦点、最近两分钟内有操作时保持活跃。服务端使用自身时钟计算同一会话相邻心跳的间隔，上限 30 秒。后台、闲置、长时间断网的间隔不补计；最后不足一个心跳周期的时长可能不计入。阅读长文时滚动可续计。

暂停或恢复时串行发送状态，恢复使用新会话 ID，避免网络请求尚未返回时丢失后台事件。每个账号共用一把数据库时钟锁；不同标签或设备的活跃租约不能叠加时长。跨午夜间隔按北京时间分到相应日期。

## 维护位置

- 首页布局：`src/app/page.tsx`。
- 三项统计、时间切换、三个榜单及参与表单：`src/components/HomeLearningDashboard.tsx`。
- 全站计时入口：`src/components/StudyTimeTracker.tsx`，在根布局挂载。
- 请求串行与恢复逻辑：`src/lib/study-heartbeat.ts`；计时路径、显示和输入规则：`src/lib/study-stats.ts`。
- 数据库表、RLS、统计及计时函数：`supabase/migrations/202610210001_learning_rankings.sql`。
- 自动检查：`npm run check:rankings`。PGlite 在本地运行真正的 PostgreSQL 引擎，数据仅存在测试进程内，不访问正式 Supabase。

检查覆盖路由、后台与闲置判断、请求未完成时的暂停恢复、SQL 重复执行、权限、未登录拒绝、退出榜单、并列、跨七日边界、大于 1,000 条数据、自评排除、服务端心跳、多会话和长间隔。测试依赖只列在 `devDependencies`，不会打入浏览器。
